# 附近商户与个人消息

## 页面行为

`map.html` 的附近推荐使用真实商户查询。卡片展示图片、名称、评分、评价数量、人均价格、商圈、地址和距离，卡片及分布示意中的编号都链接到现有 `shop-detail.html?id=...`。支持分类、3/5/10/20 公里范围和每页 10 家的分页；距离单位为米，按直线距离由近到远排序。

浏览器定位仅在用户点击“使用我的位置”时申请。没有定位权限时默认使用杭州示例坐标 `(120.149993, 30.334229)`，页面明确标注示例位置；用户可在真实定位与示例位置之间切换。分布区根据真实商户坐标绘制，是分布示意图，不提供道路底图、路线规划或导航。当前位置保存在本机浏览器中，消息页复用该位置。

`messages.html` 展示当前账号最近 30 天内、按时间倒序的最多 50 条真实动态：

- **收到点赞**：其他用户对自己笔记的点赞，时间来自现有 Redis 点赞有序集合。旧笔记收到的新点赞也能展示；自己给自己点赞不生成收到点赞消息。
- **笔记动态**：自己发布的笔记，以及关注作者在建立关注之后发布的笔记。
- **附近新店**：当前所选位置 5 公里内、近 30 天创建的商户，依据 `tb_shop.create_time`。

消息提供分类筛选、手动刷新和页面可见时每分钟自动刷新，并链接到对应笔记或商户详情。未登录时显示登录入口；接口出错显示错误和重试入口；无真实记录时显示空状态。

该页面是从现有业务记录生成的近期动态视图，不是独立持久化通知收件箱。取消的点赞不再展示；只有总点赞数而没有 Redis 点赞用户及时间的历史数据，无法还原成有时间、发送者的单条消息。此次没有新增消息表，也没有写入或补造历史消息。

## 后端接口与权限

- `GET /shop/nearby?x=...&y=...&radiusKm=5&typeId=...&current=1`：公开读取附近商户。分类可省略；经纬度必须有限且位于合法范围；半径允许 0.1～20 公里，页码允许 1～1000。查询直接读取当前数据库，新增商户无需先维护 Redis GEO 索引便可出现在结果中。
- `GET /messages?x=...&y=...`：必须登录；坐标成对提供，也可均省略以只查询笔记与点赞动态。用户身份仅取自服务端 `UserHolder`，不接受客户端指定收件人账号。

`DiscoveryMapper` 使用绑定参数执行距离及用户关联查询。消息接口返回标题、内容、图片、目标内容 ID 和时间，不返回手机号、密码或登录凭据。现有登录拦截器继续保护消息接口。
