# 2026-10-14 中间件吞吐压测报告

本报告记录当前部署和指定操作模型下的实测容量。完成 38 个 JMeter 档位和 Redis 官方工具交叉验证；JMeter 测量档位、数据准备、核验与清理样本全部成功。

## 最核心的结果

| 对象与操作 | 可引用的测量值 | 条件 |
|---|---:|---|
| Redis 基础 GET | **37,115.68 次/秒，约 3.7 万** | 1KiB 值、单个热点 Key、128 连接、Pipeline=128；官方 redis-benchmark 完成 300 万次请求，约 81 秒 |
| Redis 项目秒杀 Lua | **3,803.22 次/秒，约 3,800** | 原项目 seckill.lua、32 连接、不使用 Pipeline；预热后测量 60 秒，包含库存校验/扣减、预占和 Pending 写入 |
| MySQL 主键查询 | **72,050.67 次/秒，约 7.2 万 QPS** | 10,000 行、每行 1KiB、热缓存、64 连接；预热后测量 60 秒 |
| MySQL 单库存热点订单事务 | **752.47 笔/秒，约 750 TPS** | 订单插入＋同一库存行条件扣减＋COMMIT，4 连接；预热后测量 30 秒 |
| MySQL 分散库存订单事务 | **11,128.75 笔/秒，约 1.1 万 TPS** | 相同表结构与事务，64 个库存行、64 连接；20 秒档位，128 连接复测为 11,055.70 TPS |
| RabbitMQ 持久化消息收发 | **28,398.93 条/秒，约 2.8 万** | 74B JSON、单个 durable classic 队列、4 发布者、4 消费者、每 1,024 条等待 Confirm、逐条手动 ACK；测量 60 秒 |

Redis Lua 的独立 20 秒档位最高为 4,158.40 次/秒；MySQL 热点事务的正式短档最高为 762.90 TPS。RabbitMQ 一分钟复测中的最高 20 秒窗口为 33,587.20 条/秒，其整分钟均值为上表的 28,398.93 条/秒。面试优先引用上表的较长测量结果，并说明操作模型。

上述读、写、事务和消息单位不能相互替换。组件直接压测不包含 Spring Boot 请求处理、连接池等待、状态查询和全部消费者业务逻辑；RabbitMQ 的测试消费者只接收并 ACK 消息，不写 MySQL。项目默认 300/s 入口限流配置保持原值，这组组件容量测试直接连接中间件。

## 环境与计数口径

| 项目 | 当前测试条件 |
|---|---|
| 压力机 | 本机 Windows，JMeter 5.6.3 CLI，JDK 21 |
| Redis | 虚拟机 192.168.100.129:6380，Redis 6.2.6，AOF 未启用 |
| MySQL | 本机 MySQL 9.5.0，Connector/J 9.5.0；innodb_flush_log_at_trx_commit=1、sync_binlog=1、binlog 开启，max_connections=151 |
| RabbitMQ | 本机 Docker，RabbitMQ 4.3.4；消息持久化、Publisher Confirm、mandatory 路由、手动 ACK；测试消费者 prefetch=128 |

JMeter 前 5 秒作为预热，不纳入正式窗口；按窗口内开始并完成的成功样本计数。初始化和清理样本不纳入吞吐。MySQL 点查另用每 32 个串行查询汇总一个 JMeter 样本，减少记录开销；SQL 没有合并，每次仍是一条独立主键查询。单请求记录方式的交叉测试为 68,756.95 QPS，汇总记录方式进入约 7 万 QPS 平台。

RabbitMQ 的一次 JMeter 样本是整批 Confirm 成功，吞吐按成功批次数乘以批大小换算为消息/秒。其 P95/P99 是整批等待 Confirm 的耗时，不能解释为单条消息延迟；MySQL 分组查询的延迟也只能解释为整组耗时。

## 持续窗口的波动

| 场景 | 第一个 20 秒窗口 | 第二个 20 秒窗口 | 第三个 20 秒窗口 | 整段 60 秒均值 |
|---|---:|---:|---:|---:|
| 秒杀 Lua，次/秒 | 3,548.90 | 3,731.25 | 4,126.80 | 3,803.22 |
| MySQL 主键读，次/秒 | 73,240.00 | 71,780.80 | 70,931.20 | 72,050.67 |
| RabbitMQ，消息/秒 | 26,419.20 | 24,780.80 | 33,587.20 | 28,398.93 |

每个窗口都排除跨越窗口边界的批次，因此三个窗口的计数之和会略小于直接统计整个 60 秒窗口的计数。RabbitMQ 波动较明显，建议面试引用约 2.8 万条/秒的整段均值，不把 3.36 万条/秒的短窗峰值包装成长期容量。
