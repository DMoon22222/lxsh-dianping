## 修复内容

| 问题 | 原因 | 修复后行为 |
| --- | --- | --- |
| 首页搜索无反应 | 搜索输入框没有绑定关键词、提交事件和结果页 | 搜索按钮及回车均进入商户结果页，支持名称、商圈及地址关键词 |
| 个人主页笔记无法打开 | 笔记卡片缺少点击事件；关注动态中引用的详情跳转方法也未定义 | 自己及他人主页的笔记可通过鼠标或键盘进入详情 |
| 上传成功后图片空白 | 后端默认图片目录少了一层 `nginx-1.18.0`；前端手写 multipart 边界；图片路径格式不统一 | 修正默认目录；使用浏览器生成的 multipart 边界；统一 `/blogs/…`、`blogs/…`、`/imgs/blogs/…` 路径 |
| 历史上传图片无法访问 | 3 张图片仅存在于旧的静态资源目录 | Nginx 优先使用当前目录，缺失时兼容读取旧目录；旧图片保留在原位置 |
| 未登录首页报服务器异常 | 点赞状态查询直接访问空的 `UserHolder` | 未登录时返回未点赞状态，公开笔记及其点赞名单可以正常阅读 |
| 笔记作者不存在导致整篇文章失败 | 读取作者信息时未检查空用户 | 继续展示文章，并使用“用户已注销”作为作者名称 |
| 卡片被大图撑开、留白过多 | 图片没有固定展示比例，Flex 同行卡片默认拉伸 | 封面统一比例，卡片按内容排列，图片缺失时显示占位图 |
| 文章缺少标题、无关联商户时报错 | 详情页没有展示标题，始终请求商户信息，手写轮播阻止滚动 | 展示标题、完整正文和多图；未关联商户时正常阅读；图片支持滑动及按钮切换 |
| 接口网络异常时再次报 JS 错误 | 直接读取不存在的 `error.response.status` | 网络失败、超时和未登录均有明确提示 |
| 中文与 `&`、`+` 等搜索条件错误 | 参数未编码，`0`、`false` 也被过滤 | 参数正确编码，合法的零值及布尔值保留 |
| 发布时重复点击、上传未完成即发布 | 缺少加载状态、数量及基本输入检查 | 上传和发布期间阻止重复操作；最多 9 张图片、每张最多 5MB；检查标题和正文/图片 |

还修复了读取型评分组件使用无效 `v-model` 表达式、商户详情购买操作引用失效全局 Token、登录后未返回原页面、关注流重复加载等相关问题。详情页正文保留常见段落、换行和强调格式，并去除脚本及事件属性。

## Chrome 搜索无响应补充排查

用户反馈 Codex 浏览器可以搜索，但 Chrome 中输入内容并按回车没有反应。已在用户原有 Chrome 标签页 `http://localhost:8080/index.html` 复现：该标签页仍显示旧版首页，标题为“乐享生活”，占位文字为“请输入商户名、地点”，且没有新版的“搜索”按钮。服务端当前返回的首页标题为“首页 - 乐享生活”，已包含搜索按钮和回车事件。问题是 Chrome 中的页面尚未更新到已发布版本。

在同一 Chrome 标签页刷新后，回车搜索 `KTV` 正常跳转并显示 4 个商户，中文关键词 `火锅` 正常显示 2 个商户，无需移除搜索框或重启后端。

为避免更新后继续使用未经校验的旧文件，实际 Nginx 配置的 `location /` 增加了 `Cache-Control: no-cache` 响应头，允许浏览器保留缓存，但下次请求先向服务器校验版本；已打开的旧页面仍需要刷新才能加载新代码。`nginx -t` 和配置重载成功，首页、`index.html`、商户列表、共享 JS 和修复 CSS 均返回 HTTP 200 及此响应头。图片上传的专用路径和 API 代理配置未调整。

本次补充备份与验证位于 `.codex_out/frontend-repair-20261029/chrome-search-cache/`：`nginx-before.conf`、`nginx-after.conf`、`published.json`、`http-verification.json` 和 `chrome-search-after.png`。本次只调整 Nginx 缓存校验设置，没有再次修改搜索业务代码或数据库。
